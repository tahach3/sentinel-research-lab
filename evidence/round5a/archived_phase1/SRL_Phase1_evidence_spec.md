# SENTINEL RESEARCH LAB — PHASE 1 EVIDENCE SPECIFICATION

Companion to `SRL_Phase1_catalog_snapshot.sql`.
Defines canonical serialization, evidence identifiers, execution procedure,
per-group notes, and unresolved assumptions.

---

## 1. Canonical serialization (authoritative)

Identical to the Phase 2 digest specification ND-001, so evidence digests and
design digests are computed the same way.

**Value rendering**

| Type | Rendering |
|---|---|
| NULL | `\N` (backslash, capital N) |
| text / name | raw UTF-8 bytes, no trim, no case fold |
| boolean | `t` / `f` |
| integer, bigint | base-10, no padding, no leading `+` |
| numeric | `to_char` fixed scale as declared per column |
| oid | **prohibited as digest input** — unstable across dump/restore |
| timestamp | **prohibited unless it is itself the evidence** |

**Framing**

- values joined by `U+001F` (unit separator, `chr(31)`)
- records joined by `U+001E` (record separator, `chr(30)`), trailing separator present
- records sorted by `row_key` under `COLLATE "C"`
- file encoding UTF-8, LF line endings, no BOM

**Digest**

```
encode(sha256(convert_to(canonical_set,'UTF8')),'hex')
```

Empty set digest is fixed and testable:

```
e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855
```

G01 runs this as a self-test. A different value voids the pack.

**On JSON.** An NDJSON rendering may be produced for convenience, but it is
**not** authoritative for hashing. JSON numeric rendering is not byte-stable
across producers (trailing zeros, exponent form, `numeric` vs float), which
silently changes digests. The separator form above is the hashed artifact;
NDJSON, if produced, is a derived view.

**Independence.** Every digest in this pack uses only built-in `sha256()`.
No `research.*` function is called anywhere in the bundle, so evidence is never
generated by the code under review.

## 2. Evidence identifiers

Two levels. A Revision 8 citation uses both.

**Set identifier** — fixed, one per query:

```
EV-DRIFT-001            EV-DRIFT-002
EV-BASELINE-001..006    EV-BASELINE-DISCOVERY-001..002
EV-ROLE-001             EV-ROLE-002
EV-SCHEMA-001           EV-SCHEMA-002
EV-EXT-001
EV-FUNCTION-001         EV-FUNCTION-002
EV-FUNCTION-ACL-001     EV-FUNCTION-ACL-002
EV-FUNCTION-EXEC-001
EV-TABLE-001            EV-TABLE-ACL-001
EV-TABLE-WRITE-001      EV-TABLE-WRITE-002
EV-COLUMN-ACL-001       EV-COLUMN-EFF-001
EV-VIEW-001             EV-SEQUENCE-001
EV-TRIGGER-001          EV-POLICY-001
EV-CONSTRAINT-001       EV-CONSTRAINT-002
EV-DEFACL-001           EV-DEFACL-002
EV-RESERVATION-001      EV-CUTOVER-001
```

**Row key** — derived from natural catalog keys, never from query row number,
so it survives re-capture and re-ordering. Every query emits `row_key` as its
second column.

| Set | Row key form |
|---|---|
| roles | `rolname` |
| membership | `member \| granted \| depth` |
| functions | `schema.name(identity_args)` |
| function ACL | `schema.name(identity_args) \| grantee \| privilege` |
| function exec | `schema.name(identity_args) \| role` |
| tables | `schema.table` |
| table ACL | `schema.table \| grantee \| privilege` |
| table write | `schema.table \| role \| privilege` |
| column ACL | `schema.table.column \| grantee \| privilege` |
| default ACL | `defaclrole \| schema \| objtype \| grantee \| privilege` |

**Citation format for Revision 8**

```
EV-FUNCTION-ACL-001#research.reserve_capacity(uuid,integer)|PUBLIC|EXECUTE
EV-TABLE-WRITE-001#research.capacity_ledger|research_app|DELETE
```

Phase 3 requires every inventory row to carry one of these or an `ND-NNN`.
A row with neither is a defect — an invented row has nothing to cite.

## 3. Execution procedure

```bash
psql --no-psqlrc --set ON_ERROR_STOP=1 --pset footer=off -F $'\t' -A -f SRL_Phase1_catalog_snapshot.sql
```

1. Connect using an existing `pgpass.conf` or `PGSERVICEFILE` entry **only**.
   Any other credential path returns `BLOCKED_NO_LIVE_CATALOG`. Do not read a
   connection string out of the n8n credential store — that is a secret read.
2. Run the whole file in one session. Do not split it across transactions.
3. **Stop immediately if** `EV-BASELINE-001.version_guard = 'BLOCKED'` or the
   empty-digest self-test fails.
4. Run G19 discovery, fill the G20 placeholders, record every substitution.
5. Verify `EV-DRIFT-001 = EV-DRIFT-002`. If they differ the pack is void.
6. Write artifacts to `$env:TEMP\srl-schema8-evidence-<timestamp>\`, one file
   per evidence set, plus `MANIFEST.sha256`.

The bundle ends in `ROLLBACK` and is safe to run twice.

### The three notes that matter most

**G07 — the inverted default.** `proacl IS NULL` does not mean "no grants". It
means `acldefault('f', owner)` applies, which grants **PUBLIC EXECUTE**. An
executor reading `proacl` raw sees NULL and records "no PUBLIC EXECUTE" — the
exact inversion behind Codex #1. Every ACL read in this bundle is wrapped in
`COALESCE(acl, acldefault(type, owner))`.

**G12 — the opposite default.** Columns are the reverse case:
`acldefault('c', owner)` is the *empty* ACL, so `attacl IS NULL` genuinely
means "no column-specific grants; the table ACL governs". Applying the G07
reasoning to columns produces an error in the other direction. G12 therefore
deliberately does **not** wrap `attacl` in `acldefault`, and the comment in the
SQL says so.

**G18 — the provenance that settles #2.** An `ALTER DEFAULT PRIVILEGES` rule
applies only to objects created by the role it targets (`defaclrole`).
`EV-DEFACL-002` joins that against actual `relowner` per table. Any table whose
owner has no matching rule falsifies the Revision 7 inference for that table
specifically.

### Three columns that prevent the recurring error

Every effective-privilege query emits these separately rather than one
`effective` flag:

- `granted_direct` / `granted_via_public` / `granted_via_inherit` / `set_role_only`
- `superuser_derived` — `has_*_privilege()` is unconditionally true for
  superusers, so `postgres` shows write everywhere. Record it as
  superuser-derived; never report it as a discovered writable role.
- `exercisable` — privilege **AND** schema USAGE. `has_table_privilege()` and
  `has_function_privilege()` do **not** check schema USAGE, so freeze scope
  must be driven by `exercisable`, not the raw privilege.

`set_role_only` is the one most likely to be missed: a NOINHERIT role holds no
inherited privilege but can still `SET ROLE` and write. That is a live path
through the boundary and it must appear in the matrix.

## 5. Secret safety

`EV-BASELINE-DISCOVERY-002` classifies every candidate column with
`secret_risk`. Rules:

- No `SELECT *` anywhere in G20.
- Every column named in a G20 query must have `secret_risk = false`.
- Permitted credential fields: identifier, provider/model reference, status,
  non-secret metadata.
- Never selected: API keys, access tokens, passwords, encrypted payloads,
  private keys, complete credential values.

The discovery query reads column **names** from `pg_attribute`. It reads no
column values.

## 6. Unresolved assumptions

Four items. The first three are resolved mechanically by G19 output; the
fourth needs a decision.

1. **Application table and column names (G20).** Not assumed anywhere. G19
   discovers them; the executor fills the templates and records the mapping.
   If a placeholder has no discovered counterpart, return
   `BLOCKED_MISSING_CATALOG_DETAIL` naming it. Do not substitute a plausible
   name — that is the Revision 7 failure mode.

2. **Original and legacy reservation table names.** Same treatment. State
   A/B/C cannot be evaluated until both names are supplied from G19.

3. **PostgreSQL major version.** Bundle requires 11+. G01 guards it. Below 11
   there is no built-in `sha256()` and no `prokind`; do not hand-adapt.

4. **Column-effective row volume.** `EV-COLUMN-EFF-001` is
   tables × columns × roles × 4 privileges, restricted to login-capable roles
   plus the four named runtime roles. On a wide schema this can reach tens of
   thousands of rows. It is bounded by `statement_timeout`. If it times out,
   narrow the role set to those with any table privilege from
   `EV-TABLE-WRITE-001` and **record the narrowing in the manifest** — an
   unrecorded narrowing makes the completeness claim false.
